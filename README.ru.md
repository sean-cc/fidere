**Ассистент, который всегда включён: пока вас нет, он выполняет задачи по расписанию — и отчитывается за них.**

Fidere — это ассистент, который остаётся включённым. Вы общаетесь с ним в браузере, задаёте вопросы, сбрасываете ему идеи, чтобы они не потерялись; а когда вас нет рядом, он сам работает по своему расписанию — доводит задачу до конца без присмотра, сообщает результат и сам останавливается, когда задача выходит за бюджет.

Fidere — это латинское слово **«доверять»**. Доверие возникает не из более умной модели. Оно складывается из трёх простых вещей: **сделанное можно проверить, сломанное можно откатить, а потраченное отражено в учёте**.

## Чем он отличается

### Достаточно маленький, чтобы прочитать самому

Одна зависимость — [pi coding agent](https://github.com/earendil-works/pi), который Fidere использует как библиотеку, так что устанавливать `pi` CLI самому не нужно. Никакого фронтенд-фреймворка, сборщика и CDN — около 8 300 строк чистого JS/CSS. Никакой базы данных, очереди сообщений и второго сервиса — `node scripts/start.mjs` и есть весь путь запуска. Workflow — это не новый язык, который нужно учить; это несколько файлов в вашей собственной директории.

### Вы не платите дважды за одну и ту же историю

Большинство ассистентов-автоматов — это одна бесконечная сессия, где каждый ход заново отправляет модели всю историю — поэтому чем дольше они работают, тем медленнее и дороже. Fidere поступает наоборот:

- **Одна сессия на задачу, которая выбрасывается по завершении.** Задачи передают друг другу лишь резюме в несколько сотен слов, а не весь протокол.
- **Шаги, не требующие суждения, вообще не доходят до модели.** Скачивание, конвертация, проверка и уведомление — это скрипты: 0 токенов.
- **Дешёвые модели решают, дорогие — выполняют.** Маршрутизация, суммаризация и форматирование работают на лёгкой модели; на более дорогую уходит только трудная работа.
- **У каждой задачи есть потолок бюджета.** Выход за него останавливает задачу, а в журнал записывается, до чего она дошла и сколько потратила.

### «Готово» — это не то, что может решать модель

У каждой задачи есть исполняемая проверка; ненулевой код выхода означает, что она не готова. Сбои эскалируются в три шага: повтор на той же модели → повтор на более сильной → уведомить вас и остановиться. Он не будет тихо молотить до утра. Повторный запуск не может задвоить побочный эффект (два уведомления, два заказа). Сессия, команды, стоимость и результат каждой задачи сохраняются, поэтому неудачный запуск можно воспроизвести, а не угадывать.

### Расходы берутся из реального эндпоинта

Каждый ответ несёт в себе расход токенов и собственную цену поставщика для **фактически вызванного эндпоинта** — пиковые/непиковые тарифы DeepSeek, цена за токен OpenRouter, официальные страницы Zhipu, Moonshot, Aliyun и Anthropic, — а не статичный прайс-лист. Прокси и ваши собственные шлюзы оцениваются по настроенной вами стоимости. [Правила ценообразования по эндпоинтам →](docs/pricing.md)

### Он никогда не подменяет модель на дорогую за вашей спиной

Новые сессии начинаются с модели, которую вы видите и можете сменить. Если при повторном открытии сессии пришлось сменить модель, об этом сообщается над перепиской — замена может стоить в несколько раз дороже, и такое нельзя оставлять в лог-файле.

## Возможности

### Диалог: говорите всё, что у вас на уме

- **Непрерывные сессии** — можно продолжать разговор; когда контекст заполняется, он автоматически суммаризируется, вместо того чтобы агент забывал, на чём остановился.
- **Заметки, которые можно открыть** — идеи, выводы и задачи записываются в markdown, который можно открывать, редактировать и искать, а не в чёрный ящик.
- **Живая трансляция** — размышления и вызовы инструментов транслируются вживую, сворачиваются по завершении ответа и раскрываются заново для каждого ответа.
- **Возврат по хронологии** — хронология справа одним кликом возвращает к более раннему запросу; чтение истории не утаскивает вас вниз.
- **Ветвление и восстановление** — отредактируйте ранее отправленное сообщение и отправьте его заново в новой ветке; копируйте ответы, повторяйте отклонённые запросы, восстанавливайтесь после обрыва потока.
- **Сессии и модели** — управление сессиями, переключение моделей, выбор модели для новых сессий, прикрепление изображений и файлов.
- **Семь языков интерфейса** — English, 简体中文, 繁體中文 (台灣 / 香港), 日本語, 한국어 и Русский.
- **Палитра команд** — одна палитра `/` для команд, моделей, навыков и шаблонов промптов ([горячие клавиши](#горячие-клавиши)).
- **Не давать Mac заснуть** — необязательный `caffeinate` на время длительных задач.

### Задачи: выполняются, пока вас нет

- **Расписание** — каждые N минут, ежедневно в заданное время или только в будни.
- **Жёсткий бюджет** — останавливается, а не тихо прожигает деньги.
- **Исполняемая проверка** — слова модели «готово» это подсказка, а вывод даёт код выхода.
- **Эскалация и уведомление** — та же модель → более сильная → сообщить вам и остановиться.
- **Один запуск на запланированный момент** — плюс стабильный `FIDERE_RUN_KEY`, чтобы задача сама отсекала дубли внешних действий (заказ, отправка).
- **Журнал и ежедневный отчёт** — что выполнялось, что прошло, сколько стоило.
- **Навёрстывание** — пропущенные задачи выполняются после перезагрузки или пробуждения, а отчёт указывает, насколько они опоздали.

### Workflows: одна страница инструкций и несколько скриптов

Никаких блок-схем, нового синтаксиса и движков оркестрации. Workflow — это директория:

```text
workflows/finance-daily/
├── SKILL.md       ← инструкции для модели, обычным текстом
├── fetch.mjs      ← детерминированная часть в виде скрипта: 0 токенов
└── verify.mjs     ← проверка; код выхода 0 означает «готово»
```

Небольшой блок frontmatter в начале `SKILL.md` читает планировщик Fidere; основную часть читает модель:

```markdown
---
name: finance-daily
description: Каждое утро сводить финансовые новости в короткую сводку.
schedule: daily 08:00
budget: ¥0.4
verify: node verify.mjs
notify: echo "$FIDERE_TASK ok=$FIDERE_TASK_OK" >> notify.log   # any shell command
tools: read,write,bash
---

# Ежедневная финансовая сводка

1. Сначала запустите `node fetch.mjs` (не пишите свой curl). Результат: `out/raw.json`
2. Прочитайте `out/raw.json` и отберите 5 событий, которые скорее всего сдвинут индекс.
   Мелкие новости про отдельные компании пропускайте.
3. Запишите `out/digest.md`: по два предложения на событие, затем пометку «на что смотреть сегодня».
4. Запустите `node verify.mjs`, чтобы проверить свою работу.

Никогда не выдумывайте цифры. Чего нет в `raw.json`, того нет и в файле.
```

Три слоя, у каждого одна задача: **frontmatter для кода** (когда, сколько, как проверять, кого уведомлять), **основной текст для модели** (как, что важно, чего не делать), **скрипты для машины** (детерминированная работа). Доменное содержимое целиком живёт в вашей собственной директории — Fidere ничего о нём не предполагает.

Формат — это стандарт [Agent Skills](https://agentskills.io/specification), так что уже имеющийся у вас skill можно просто положить в `workflows/` и поставить на расписание без переписывания.

### Граница безопасности для работы без присмотра

Когда вы общаетесь, ошибку видно сразу; когда никто не смотрит, ошибка работает всю ночь. Поэтому это решается не промптом с просьбой «вести себя хорошо», а жёсткими границами:

- **Уровни прав:** только чтение / запись только в назначенную директорию / выполнение любых команд. Первые два — по умолчанию; третий нужно включать явно
- **Опасные действия блокируются на уровне инструментов:** удаление, force-push, загрузка на внешние хосты и правки файлов учётных данных отклоняются и логируются, а не оставляются на усмотрение модели
- **Заблокированная рабочая директория:** задача работает внутри собственной одноразовой директории, а вне неё — только чтение
- **Всё зафиксировано:** сессии, команды, стоимость и результаты сохраняются, поэтому запуск можно воспроизвести

Fidere слушает `127.0.0.1`, однопользовательский и принимает один токен доступа. Он предназначен для запуска вами — или каждым для себя, — а не как мультитенантная платформа.

## Быстрый старт

### Требования

- Node.js **22.19+**
- API-ключ поддерживаемого провайдера (Anthropic, OpenAI, Google, DeepSeek, OpenRouter, Moonshot, MiniMax, xAI, Groq, Mistral и другие)
- macOS, Linux или Windows. Только две вещи привязаны к macOS: необязательное предотвращение сна (`npm run start:awake`) и `caffeinate` во время длительных задач. Всё остальное работает везде, где работает Node.

### 1. Клонирование и установка

```bash
git clone https://github.com/sean-cc/fidere.git
cd fidere
npm install --ignore-scripts
npm run setup
```

`--ignore-scripts` пропускает lifecycle-скрипты npm, поэтому при установке ничего не выполняется — Fidere они не нужны. `npm run setup` просит выбрать провайдера и ввести его API-ключ, после чего сохраняет его в `~/.pi/agent/auth.json`. **Устанавливать pi CLI не требуется**: он приходит как обычная зависимость.

### 2. Запуск сервера

```bash
npm start
```

### 3. Открыть и войти

Откройте <http://localhost:3000> и вставьте токен доступа, напечатанный при запуске. Токен также хранится в `~/.pi/agent/fidere-token` (права `0600`). Сессионный cookie действует 30 дней.

### 4. Выбрать модель

Выберите модель в селекторе в левом нижнем углу. Если не выбирать, Fidere использует сохранённую модель по умолчанию, затем собственную рекомендацию (см. [FAQ](#faq)), затем резервную таблицу pi по провайдерам.

Всё готово — можно общаться или написать первый workflow в `workflows/`.

## Установка и настройка

Быстрый старт выше — рекомендуемый путь. Всё остальное необязательно.

### Проверка обновлений

При каждом запуске `npm start` спрашивает у npm, не вышла ли более новая версия pi. В интерактивном терминале он спрашивает, обновляться ли; при согласии сначала устанавливает новую версию, затем запускает сервер. В неинтерактивном окружении он лишь печатает доступную версию и запускается как обычно. Установите `FIDERE_SDK_UPDATE=off`, чтобы пропустить проверку, или `auto`, чтобы обновляться без вопроса.

### Использовать переменную окружения

```bash
export ANTHROPIC_API_KEY=sk-ant-...
npm start
```

`OPENAI_API_KEY`, `GEMINI_API_KEY`, `DEEPSEEK_API_KEY` и прочие переменные окружения провайдеров тоже работают. pi CLI не требуется.

### Порт и хост

```bash
PORT=8080 npm start          # по умолчанию 3000
HOST=0.0.0.0 npm start       # только для доверенных сетей, см. ниже
```

### Управление доступом

Каждый API-маршрут требует токен доступа: он читается из `FIDERE_TOKEN` или генерируется при первом запуске в `~/.pi/agent/fidere-token`. Войдите один раз, открыв `/#token=<token>` или вставив его в форму входа, — фрагмент никогда не попадает ни на сервер, ни в лог прокси. Запросы, меняющие состояние, также требуют CSRF-токен с двойной отправкой, который UI присылает автоматически. [Все параметры управления доступом →](docs/access-control.md)

По умолчанию сервер слушает `127.0.0.1`. Не выставляйте его напрямую в интернет. Используйте обратный прокси с TLS или приватный туннель.

## Горячие клавиши

| Клавиши | Действие |
|----------|--------|
| `Enter` | Отправить сообщение |
| `Shift+Enter` | Вставить новую строку в поле ввода |
| `/` | Открыть палитру команд (команды, модели, навыки, шаблоны промптов) |
| `↑` / `↓` | Перемещаться по результатам палитры |
| `Tab` / `Enter` | Принять выбранный пункт палитры |
| `Esc` | Закрыть палитру команд или диалог возобновления сессии |
| `↑` / `↓`, `Home` / `End` | Переход между более ранними запросами, когда фокус на хронологии справа |

## FAQ

- **Откуда берутся цены?** Каждая модель оценивается по **фактически вызванному эндпоинту** и в валюте самого поставщика: официальные пиковые/непиковые тарифы DeepSeek, цена за токен OpenRouter, страницы Zhipu в юанях, а также опубликованные страницы/API Anthropic, Moonshot, Aliyun и Hugging Face. Остальные эндпоинты используют `cost`, заданный вами в `models.json`, а встроенная цена pi служит последним резервом. Полные правила, переопределение валюты и кеш: [docs/pricing.md](docs/pricing.md).
- **Нет моделей?** Запустите `npm run setup` или задайте переменную окружения провайдера, затем перезапустите сервер.
- **С какой модели начинаются новые сессии?** Сначала `defaultProvider`/`defaultModel` из `~/.pi/agent/settings.json`, затем собственная таблица рекомендаций Fidere (сейчас DeepSeek → `deepseek-flash`), затем встроенная таблица pi по провайдерам. `npm run setup` записывает рекомендованную модель в settings, а **set default** в любой строке списка моделей меняет её позже. Это переопределение нужно потому, что таблица pi запускает DeepSeek на `deepseek-v4-pro` — вход в 4,4 раза дороже, чем у `deepseek-flash`, и без поддержки изображений — что на свежей установке оборачивается дорогим сюрпризом.
- **Остановит ли задачи закрытие крышки?** Сервер может удерживать `caffeinate`-ассерт во время активных задач, но закрытие крышки всё равно усыпит машину, если только Mac не в режиме закрытой крышки (clamshell). Для настоящей работы 24/7 используйте постоянно включённую машину.
- **Где хранятся ключи?** `~/.pi/agent/auth.json`. API-ключи никогда не записываются в этот репозиторий.

## Разработка

```bash
npm test          # юнит-тесты: цены, markdown, модели по умолчанию, проверка SDK, планировщик
npm run smoke     # smoke-тест интерфейса в headless Chrome (нужен Chrome/Chromium)
npm run dev       # запуск с node --watch
npm run daemon    # только планировщик (--list, --run <name>, --once)
```

Об архитектуре, эндпоинтах API, локализации и обновлениях pi см. [DEVELOPMENT.md](DEVELOPMENT.md).

### Участие в разработке

Мы рады вкладу. Несколько правил, с которыми PR проходит легче:

1. Для изменений крупнее исправления бага сначала откройте issue и согласуйте подход.
2. Держите просто: без фронтенд-фреймворка, сборщика и новых runtime-зависимостей, если без них действительно нельзя.
3. Перед push запустите `npm test`; если трогали интерфейс — ещё и `npm run smoke`.
4. В PR напишите, что изменили и как проверили — достаточно скриншота или имени теста.

Строки интерфейса лежат в `public/i18n.js`, и их нужно заполнить для всех семи языков, иначе smoke-тест упадёт.
